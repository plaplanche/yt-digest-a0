# Decisions

Choices the spec leaves open, one dated line each.

- 2026-10-16: `node/` builds with `uv_build`, pins Python 3.12 through `requires-python = ">=3.12,<3.13"` and `.python-version`, and keeps ruff, mypy and pytest in the `dev` dependency group, unpinned in `pyproject.toml` and pinned by `uv.lock`.
- 2026-10-16: ruff uses its default formatter settings and the rule sets `E`, `F`, `W`, `I`, `B`, `UP`; mypy runs as `mypy --strict src tests` with no extra configuration.
- 2026-10-16: `worker/` is an ES module package checked by `tsc --noEmit` (`strict: true`, `moduleResolution: Bundler`), linted with ESLint's flat config (`@eslint/js` recommended plus `typescript-eslint` strict) and tested with `vitest run`; TypeScript is the latest version `typescript-eslint` accepts as a peer.
- 2026-10-16: the placeholder tests check that each package exposes its version (`yt_digest_node.__version__`, `VERSION` in `worker/src/index.ts`), which `service.started` will log.
- 2026-10-16: shellcheck runs pinned as `uvx --from shellcheck-py==0.11.0.1 shellcheck` on every `*.sh` file under `scripts/`, found with `find`.
- 2026-10-16: the `contracts` check passes with a message while `scripts/contracts.sh` does not exist.
- 2026-10-16: the contract code is produced by `scripts/contracts_gen.py`, a stdlib-only generator run with the node project's Python, which supports only the JSON Schema keywords the contracts use and fails on any other; the Python output is then formatted with `ruff format`.
- 2026-10-16: an enum with a `title` (only the log catalogue, `LogEventName`) becomes a Python `StrEnum` and a TypeScript `as const` array with its union type; other enums become `Literal` types and inline unions.
- 2026-10-16: each generated TypeScript file also holds a `parse<Title>(value: unknown)` function that throws on a value the schema rejects, since TypeScript types alone cannot check patterns or ranges at runtime; Pydantic models use strict scalar fields and `extra="forbid"`, and an optional non-nullable field rejects null.
- 2026-10-16: the schemas encode only the field types and constraints of 4.1 and 4.2: the "null unless `ok`" rules of the transcript result and the attributes of each log event are left to the code that produces them.
- 2026-10-16: the log `video_id` is a plain string (4.2 gives it no pattern); `ts` is checked by the pattern `YYYY-MM-DDTHH:MM:SS.mmmZ`.
- 2026-10-16: `--check` names every stale, missing or extra generated file (ignoring `__pycache__`); its test runs it on a copy of the repository.
- 2026-10-16: `emit` sets `ts` and `service`, defaults `attrs` to `{}`, raises `ValueError` when `ts` or `service` is given, and omits absent optional fields; `log(event, fields)` takes `level`, `request_id`, `video_id` and `attrs` and writes with `console.log`.
- 2026-10-16: ruff ignores `E501` in the generated `contracts/` package, whose header and docstrings come from the schemas.
- 2026-10-16: cleaning lives in `yt_digest_node.cleaning`: `parse_vtt(text) -> list[Cue]` (`Cue(start, end, lines)`, seconds as floats) and `paragraphs(cues, segments) -> list[str]`; step 2 (sponsor cuts) is left to the SponsorBlock ticket, so `segments` is accepted but not applied yet.
- 2026-10-16: VTT blocks are separated by empty lines only (a line of spaces, as in YouTube auto tracks, stays a text line); the first block starting with `WEBVTT` is the header; a block with no timing line in its first two lines is skipped; CRLF and a BOM are accepted; timestamps may omit hours.
- 2026-10-16: every `<…>` is removed as an inline tag, before entities are decoded (so `&lt;3` stays `<3`); a bracketed annotation is `[` up to the next `]`.
- 2026-10-16: a "kept cue" (5.4 step 5) is a cue with at least one kept line; gaps are compared in whole milliseconds, so a 2.0 s gap always starts a paragraph despite float rounding.
- 2026-10-16: the SponsorBlock client is `yt_digest_node.sponsorblock.fetch_segments(video_id, base_url, request_id=None, timeout=10.0) -> SponsorBlockResult(segments, state)`, on the standard library's `urllib` (no new dependency, proxies taken from the environment); the category list is encoded as compact JSON, `["sponsor","selfpromo","interaction"]`, and a trailing `/` of the base URL is dropped.
- 2026-10-16: a 200 whose body is not a JSON array of objects carrying a numeric `segment: [start, end]` counts as `error` (no segments, the log `status` stays 200); a timeout counts as a network error (status 0); `sponsorblock.call` is logged at level `info` whatever the outcome, with the `video_id` and, when given, the `request_id`.
- 2026-10-16: step 2 is applied in `paragraphs` through `in_a_segment(midpoint, segments)`, before steps 3 to 5, so a dropped cue neither counts as the previous kept line nor as the previous kept cue for the paragraph gap.
- 2026-10-16: `sponsor_ratio(segments, duration)` is 0 when the duration is not positive, and a segment clipped to nothing (fully outside [0, duration], or with end ≤ start) is ignored.
- 2026-10-16: the extractors live in `yt_digest_node.extractor`: `extract(video_id, langs)` returns `"unavailable"`, `"blocked"` or `Video(duration, tracks)` with `Track(lang, source, vtt)`; `choose_track(tracks, langs)` returns None for `no_transcript`; `extractor_from_env(environ)` picks the extractor and raises `ValueError` when `FETCHER_FAKE_YTDLP=1` comes without `FAKE_YTDLP_DIR`.
- 2026-10-16: the fake extractor returns every `<lang>.<manual|auto>.vtt` file of the directory and requires `meta.json` (a missing one raises); a `status` of `unavailable` or `blocked` is returned before `duration` is read; languages are matched exactly.
- 2026-10-16: yt-dlp is a runtime dependency, imported with `type: ignore[import-untyped]` (it ships no types); `extract_info(url, download=False)` reads the `subtitles` (manual) and `automatic_captions` (auto) of the info dict and only the `vtt` entries in the requested languages are downloaded, with `YoutubeDL.urlopen`, so that the many auto-translated tracks are never fetched.
- 2026-10-16: yt-dlp also gets a silent `logger`, so that its messages never reach stdout (the result) or stderr (the JSON log lines); a missing `duration` counts as 0.
- 2026-10-16: a yt-dlp `DownloadError` whose message contains "not a bot" (YouTube's "Sign in to confirm you're not a bot") is `blocked`; every other `DownloadError` (private, age-restricted, removed, ...) is `unavailable`; other exceptions propagate.
- 2026-10-16: `YT_DELAY_SECONDS` is `<min>-<max>` or one number of seconds; the delay is drawn with `random.uniform` before `extract_info` and before each subtitle download; the fake extractor has no delay at all.
- 2026-10-16: truncation and pages live in `yt_digest_node.pages`: `truncate(paragraphs, max_words) -> (paragraphs, truncated)` and `paginate(paragraphs, page_words) -> pages`; a word count skips the `[…]` token, which cleaning makes impossible in the text itself (every `[…]` annotation is removed).
- 2026-10-16: a paragraph that does not fit in the current page starts a new page; one longer than `PAGE_WORDS` is cut into pieces of `PAGE_WORDS` words (joined by single spaces), its last piece staying open for the next paragraphs; the `[…]` paragraph takes no room; a track with no kept text is `ok` with no page and `word_count` 0.
- 2026-10-16: the pipeline is `yt_digest_node.pipeline.transcript(video_id, langs, config, extractor, request_id)`; SponsorBlock is called only once a track is chosen, so `fetch.transcript` logs `sponsorblock` (and `source`, `sponsor_ratio`) as null for `no_transcript`, `unavailable` and `blocked`; `duration_ms` covers the whole pipeline.
- 2026-10-16: the command is `yt_digest_node.cli:main` (argparse, `transcript` subcommand); `--langs` and `TRANSCRIPT_LANGS` are comma-separated with blanks dropped; an empty language list, a `MAX_WORDS` or `PAGE_WORDS` that is not a positive integer, or `FETCHER_FAKE_YTDLP=1` without `FAKE_YTDLP_DIR` exits 2 like a bad argument, before `service.started`, with argparse's usage message on stderr.
- 2026-10-16: the end-to-end tests run the installed `yt-digest-node` script next to the test interpreter (the command `uv run --project node` runs), against the shared local SponsorBlock of `tests/conftest.py`.
- 2026-10-16: the generator supports nested objects with `properties`, which need a PascalCase `title` and `additionalProperties: false` and become named types (`ClaimedJob` in the claim response, `ErrorDetail` in the error body); the error body's root is titled `ErrorResponse`, so that it does not shadow TypeScript's `Error`; every title, of models and enums, is unique across `contracts/`.
- 2026-10-16: a field refers to another schema of `contracts/` with `{"$ref": "<file>"}`, or `{"anyOf": [{"$ref": "<file>"}, {"type": "null"}]}` when it may be null (the `transcript` of `node-result-request`); the generated Python module imports the referenced model with a relative import and the TypeScript file imports its type and its `check<Title>` function.
- 2026-10-16: each generated TypeScript object type gets an exported `check<Title>(value): string | null` (the reason a value is rejected, or null), on which `parse<Title>` throws; nested objects and references are checked through it.
- 2026-10-16: `minLength` and `maxLength` count characters (code points): Pydantic's `min_length`/`max_length`, and `[...value].length` in TypeScript; node protocol timestamps use the log `ts` pattern; `max_jobs` has no `default` in the schema, its absent value 3 is applied by the `/node/claim` route.
- 2026-10-16: the TypeScript test that the result request imports the transcript-result type reads the generated source with Vite's `?raw` import (types from `vite/client`, installed with Vitest), since the Worker package has no Node types.
- 2026-10-16: Worker tests run inside workerd with `@cloudflare/vitest-plugin` (the renamed `@cloudflare/vitest-pool-workers`, which supports Vitest 5) on `wrangler.toml`'s real D1 and R2; `test/setup.ts` applies `migrations/` with `applyD1Migrations`; route tests call the Worker's `fetch` with the test bindings, `OPS_TOKEN` overridden where needed. The package lock is written by npm 11, whose resolver handles Vitest's optional peers where npm 10's fails, and is installed with `npm ci` on npm 10.
- 2026-10-16: `wrangler.toml` names the Worker `yt-digest-worker`, sets `compatibility_date = "2026-10-01"` and gives the D1 database no `database_id` (local only); Worker types come from `@cloudflare/workers-types` with `lib: ["ES2022"]`.
- 2026-10-16: the migration `0001_init.sql` adds `NOT NULL` to the columns every row has, `CHECK` constraints for the enums of 6.3, the defaults `priority` 0, `attempts` 0, `tried_nodes` `'[]'`, `revoked` 0, and a unique `nodes.token_hash`.
- 2026-10-16: `VERSION` moves to `worker/src/version.ts`, read from `worker/package.json`, since workerd rejects an entry module exporting anything but handlers.
- 2026-10-16: a bearer is read from `Authorization: Bearer <token>` (scheme as written, one space, a token without spaces); the operator token is compared in constant time by `crypto.subtle.timingSafeEqual` on the SHA-256 digests of both values.
- 2026-10-16: any `/ops/*` request, route known or not, is authenticated first (404 when `OPS_TOKEN` is empty, else 401 on a missing or wrong bearer), then routed (404 `not_found` for an unknown route or method); a rejected bearer logs `auth.bearer.rejected` at `warn` with `surface` `ops` and `reason` `missing` or `unknown`.
- 2026-10-16: `POST /ops/reset` deletes the rows of the 6.3 tables in one D1 batch (the migrations' own table is kept) and the R2 objects listed under `transcripts/`, page by page; any request body is ignored.
- 2026-10-16: request bodies are read by `readBody(request, parse)`, which throws 400 `invalid_request` when the body is not JSON or the generated `parse<Title>` rejects it; an error thrown as `HttpError` is answered with the error body of 4.2, any other error is left to the runtime (500).
- 2026-10-16: `e2e/` uses the same TypeScript, ESLint and `typescript-eslint` versions and flat config as `worker/`, with `@types/node` 22; its Playwright projects are told apart by file name, `*.api.spec.ts` for `api` and `*.browser.spec.ts` (Desktop Chrome) for `browser`, and run with one worker, since every test resets the one shared stack.
- 2026-10-16: the tests read `WORKER_PORT`, `MOCKS_PORT` and `OPS_TOKEN` from their environment with the defaults of 5.2; Playwright writes its HTML report to `e2e/playwright-report/` (git-ignored, with `test-results/`), which the `e2e` check copies on failure to `ci-artifacts/playwright-report/`, the stack logs going to `ci-artifacts/stack-logs/`.
- 2026-10-16: `stack.sh` starts each process with `setsid` and keeps its process group id in `.stack/pids/<name>.pid`; `down` sends SIGTERM to each group, then SIGKILL after 10 seconds; a port counts as taken when a TCP connection to `127.0.0.1:<port>` succeeds, checked before anything is started; `up` also fails early when a started process exits before readiness.
- 2026-10-16: `stack.sh` passes every Worker setting of 5.2 (except the ports and the timeout) as `wrangler dev --var NAME:value`, `WORKER_URL` as `PUBLIC_URL`; an `OPS_TOKEN` set to an empty value stays empty; `wrangler dev` runs with `--show-interactive-dev-session=false`, and its `.wrangler/` build directory is git-ignored.
- 2026-10-16: the mocks server answers 404 `Not Found` in plain text to any route it does not know, like its SponsorBlock route.
- 2026-10-16: `/node/*` is routed before it is authenticated: a method other than `POST`, or a path other than the protocol's, gives 404 `not_found` without a bearer; a known route then checks the node's bearer (401 before the body) and its body. A rejected node bearer logs `auth.bearer.rejected` with `surface` `node` and `reason` `missing`, `unknown` (no node has the token's hash, the operator token included) or `revoked`.
- 2026-10-16: node tokens are `ytd_node_` plus 32 bytes of `crypto.getRandomValues` in base64url; the bodies of `POST /ops/nodes` and `POST /ops/jobs` have no contract and are checked by hand in `ops.ts` (unknown fields refused), giving 400 `invalid_request`; `LEASE_SECONDS` falls back to 600 when it is not a positive integer.
- 2026-10-16: `POST /ops/jobs` runs one D1 batch of, per id, an `INSERT … ON CONFLICT DO NOTHING` (its change count tells `enqueued` from `existing`, so an id repeated in one request is enqueued once, then existing) and an `UPDATE` raising the priority; all ids of one request share one `created_at`; `job.enqueued` is logged once per request with `count` the number of new jobs.
- 2026-10-16: a claim is one D1 batch: an `UPDATE jobs … WHERE rowid IN (SELECT … ORDER BY … LIMIT ?) RETURNING` leases the jobs, each with a `lease_id` of 32 hexadecimal characters from `randomblob(16)`, then an `INSERT INTO leases … SELECT` adds the `active` lease of every leased job of the node that has none, which within the batch's transaction are exactly the claim's; the response is sorted in the claim's order in the Worker, since `RETURNING` keeps none. `job.claimed` is logged once per job.
- 2026-10-16: the expiry sweep is one D1 batch (read the holders, insert the `lease_expired` node events, expire the leases, apply the failure handling with `RETURNING`), run after the body is validated on all four `/node/*` endpoints and before `GET /ops/jobs/<video_id>`; a lease expires when `lease_expires_at <= now`, both compared as timestamp text; `job.lease_expired` is logged at `warn`.
- 2026-10-16: a lease is `active` exactly while its job is `leased` with its `lease_id`, so a result, a release or a 422 is settled by one D1 batch whose every statement holds only while the job still has the lease (node event, lease state and `response_json`, then the job's `UPDATE … RETURNING`); a concurrent duplicate that finds the lease settled answers like a retry (the stored answer, or 409).
- 2026-10-16: the R2 object is `JSON.stringify` of the received `transcript` (key order kept), written with `onlyIf: { etagDoesNotMatch: "*" }` so that even racing writes never overwrite; any exception of the put gives 503 `storage_error`; the write happens before the D1 batch, so a lease expiring in the milliseconds between the two leaves a valid transcript stored for a 409.
- 2026-10-16: the validation of 8.4 checks its rules in the order of the spec and logs the first broken one as `reason`: `transcript_missing`, `status_not_ok`, `video_id_mismatch`, `pages_empty`, `word_count_mismatch`, or `transcript_not_null` for another outcome; words are split on `\s+`, the `[…]` token excluded; a rejected lease stores no `response_json`, so a retry of the same result gets 409 `stale_lease`.
- 2026-10-16: `job.stale_result` and `job.validation_failed` are logged at `warn`, `job.completed` (for every 200 outcome, failures included), `job.released` and `node.revoked` at `info`; `job.stale_result` carries the lease's `video_id` when the lease exists.
- 2026-10-16: a release removes the last entry of `tried_nodes` (`json_remove(…, '$[#-1]')`), which the claim appended and which is the only entry of the node.
- 2026-10-16: `DELETE /ops/nodes/<node_id>` is one D1 batch; revoking again keeps the first `revoked_at` and `state_since` and logs `node.revoked` with `leases_revoked` 0; it does not run the expiry sweep, so an expired lease not yet swept is revoked instead (`last_outcome` `lease_revoked`).
- 2026-10-16: Worker tests control the clock with `vi.useFakeTimers({ toFake: ["Date"] })`, and simulate a failed R2 write with a proxy of the real test bucket whose `put` rejects; the e2e helpers of the node protocol live in `e2e/tests/nodes.ts`.
- 2026-10-16: the daemon lives in `yt_digest_node.work` (`WorkerClient`, `Daemon`, `settings_from_env`) on the standard library's `urllib`, like SponsorBlock, with a 30 s timeout per request; an empty `WORKER_URL` or `NODE_TOKEN` counts as missing, and a missing one, a `CLAIM_BATCH` outside 1 to 10, or a `POLL_SECONDS` or `HEARTBEAT_SECONDS` that is not a positive number (fractions allowed) exits 2 like a bad argument, with argparse's usage message, before `service.started`.
- 2026-10-16: the daemon is single-threaded: a due heartbeat is sent between jobs and after each poll wait, never during a pipeline run; `jobs_in_progress` counts the claimed jobs not yet answered; in the loop, a failed heartbeat is ignored and a failed claim counts as an empty one; a 401 on any call exits 1, with `--once` too.
- 2026-10-16: a 2xx whose body the generated model rejects counts as a failed call, not retried; a result or release still failing after its retries, or answered with a 4xx other than 401, is dropped (the lease expires on the Worker); error bodies are not read.
- 2026-10-16: `worker.call` is logged once per HTTP attempt, at `info` for a 2xx and `warn` otherwise, with the job's `video_id` for `result` and `release`; a pipeline exception logs `fetch.transcript` at `error` with `outcome` `error`, the attributes of a result without a transcript, and no exception text; the pipeline gets no `request_id`.
- 2026-10-16: SIGTERM and SIGINT are handled the same way in both modes; the e2e test runs `uv run --locked --project node yt-digest-node work --once` on the lot 1 fixture `sponsorVid1`, against the mock SponsorBlock.
- 2026-10-16: the fake Google signs with a `kid` of 16 random hexadecimal characters chosen at start; `/google/authorize` needs a `redirect_uri` that parses as a URL and a `scope` holding `openid` as a space-separated word; an empty `login_hint` counts as absent, and the sign-in form repeats every other received parameter as an HTML-escaped hidden input.
- 2026-10-16: the fake Google's codes, access tokens and refresh tokens are 32 random bytes in base64url; a code is used up by any exchange attempt that names it; the token answer's `scope` is the authorize request's; HTTP Basic, when sent, takes precedence over the body's `client_id`/`client_secret` (both URL-decoded, RFC 6749 2.3.1); a refreshed ID token carries no `nonce`, and refresh tokens never expire; access tokens expire after 3600 s; userinfo answers 401 `{"error": "invalid_token"}`, and revoke answers an empty 200 and revokes nothing.
- 2026-10-16: `POST /ops/invites` needs `{"email"}` as its only field, a string containing `@`; re-inviting sets `revoked` to 0 and keeps `invited_at` and `accepted_user_sub`; `POST /ops/invites/revoke` takes any string `email`, lowercased, and revoking again answers the same 200; `GET /ops/users` sorts by `email`, then `user_sub`.
- 2026-10-16: the OAuth flow is built by hand in `worker/src/oauth.ts` (routes) and `worker/src/google.ts` (the upstream provider), with no new dependency; Google's discovery document and JWKS are fetched on every use, nothing cached; a failing discovery fetch at `POST /authorize/consent` is left to the runtime (500).
- 2026-10-16: `POST /register` ignores unknown metadata (RFC 7591 2); a body that is not a JSON object gives `invalid_client_metadata`; `redirect_uris` is checked first, so a body with both kinds of errors gives `invalid_redirect_uri`; more than 10 URIs, or a non-string one, count as invalid redirect URIs; a URI holding `#` anywhere counts as having a fragment; `client_id` is 24 random bytes in base64url.
- 2026-10-16: at `GET /authorize` a missing `client_id` counts as unknown; an empty `code_challenge` counts as missing; a `scope` given but not exactly `digest` (an empty one included) is `invalid_scope`; an error redirect keeps the redirect URI's own query and adds `state` only when the client sent one.
- 2026-10-16: the Google `state` and `nonce` (32 random bytes in base64url each) are drawn when the pending authorization is stored and first revealed by the approve redirect; approving does not use the pending authorization up (the callback does), so approving twice redirects twice with the same values; a `decision` other than `approve` or `deny` on a valid request gives 400 HTML; the consent form body is read as form-encoded whatever its `Content-Type`.
- 2026-10-16: at `GET /callback` a missing `code` counts as a failed exchange (`server_error`); an ID token is verified with the JWKS key of its header's `kid` (any RSA key when it has none), `aud` must be the string `GOOGLE_CLIENT_ID`, and it must carry a string `sub` and `email`; `email_verified` is checked before the invite, so an unverified admin is refused too.
- 2026-10-16: `auth.oauth.denied` uses `google_error` both for an `error` from Google and for a failed exchange or ID token check, and is logged at `info` for a user's `deny` and at `warn` otherwise; `ADMIN_EMAIL` is compared lowercased.
- 2026-10-16: signing in again updates the `users` row's `email` and `role` and keeps its `created_at`; the stored Google refresh token is replaced only when Google sends one; the invite's `accepted_user_sub` is set on every admitted login of its e-mail (the admin's too, when invited); the row, the invite and the code are written in one D1 batch.
- 2026-10-16: authorization codes are 32 random bytes in base64url; HTML pages are `text/html; charset=utf-8` and escape `& < > " '` as numeric references; the Worker tests stub Google with a `fetch` spy signing ID tokens with a key generated by `crypto.subtle`.
- 2026-10-16: the OAuth e2e client registers `$MOCKS_URL/client/callback` (a 404 of the mocks server) as its redirect URI, so that the browser ends the flow on a page whose URL holds the code.
